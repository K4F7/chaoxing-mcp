# Android 用预排本地闹钟提醒，而不是后台定期抓取

Status: superseded by [ADR-0002](./0002-local-mcp-over-app.md)

Android 上要在正确的时刻提醒用户，有两条路：让 App 定期在后台醒来抓取、判断是否该提醒；或者在一次前台同步之后，把未来每一次该响的提醒直接排进系统闹钟。我们选后者。

**为什么不选后台抓取。** Android 的后台执行窗口由系统裁量，Doze 与厂商省电策略会把周期任务推迟到不确定的时刻，甚至完全不执行。这类失败没有任何用户可见的迹象——App 图标还在，界面还是上次的样子——正是[静默失效](../../CONTEXT.md)最典型的形态。一个会安静漏掉截止提醒的提醒工具，比没有提醒工具更糟，因为用户会依赖它而停止自己盯。

**为什么用免授权的精确闹钟权限。** 精确闹钟有两种申请方式：一种需要用户在系统设置里手动开启，默认拒绝；另一种在安装时即授予，但受应用商店政策限制。本工具通过侧载分发、不上架商店，因此商店政策不适用，我们选择安装即授予的那一种。理由同上：需要用户手动开启的权限一旦没开，提醒会静默地全部失准，而工具无法在事后知道自己失准了。

**这个选择带来的约束。**

- 提醒的准确性取决于最后一次成功同步时的数据。截止时间在同步之后被老师改动，已排的闹钟不会自己跟上，直到下一次前台同步重排。
- 系统对单个应用的并发闹钟数量有硬上限。提醒规则数与待办数的乘积必须留在上限之内，超出时的取舍必须是显式的、可见的，不能悄悄丢弃末尾的提醒。
- 设备重启会清空已排闹钟，必须在开机后重新排一遍。
- 每次同步之后必须整体取消并重排，而不是增量更新，否则已删除或已完成的事项会留下孤儿闹钟。这要求每条提醒有稳定的标识，使重排能准确命中上一轮排下的那一条。
